# Backgammon Mastermind audit — September 6, 2026

**Verdict:** A useful offline casual game with a good interaction foundation. It needs correct turn rules, durable game history, and a compelling play → review → improve loop before it deserves the “Mastermind” promise. More themes and animation should come later.

Scope: `main` at `fd4d0f55dc63c846280e336c0cf03333c8d2dc5f`; code review, production web exports, unit tests, and inspection of the deployed home, game, settings, and Learn flows. Live deployment observations do not establish its exact Git revision. No physical iOS/Android device was available. Performance numbers below are export sizes and a Node microbenchmark, **not native cold-launch measurements**.

## Remaining findings, in priority order

### P0 — Turn legality does not enforce maximum dice usage or the higher die

**Confirmed by executing two positions.** `src/lib/game/moves.ts:getLegalMoves` checks individual moves, then returns them without considering whether the whole roll can be used. `applyMove` consequently allows a player to strand a usable die. This affects humans, hints, compound paths, and the AI.

Both reproductions use white to play 1–2, with one white checker on the bar and 14 on point 6. All omitted points are empty:

| Position | Black checkers | App currently permits | Required result |
|---|---|---|---|
| Must use both dice | 2 on 22; 2 on 4; 11 on 19 | `bar → 24` using 1, then no move | Only `bar → 23` using 2: it leaves `6 → 5` using 1 available |
| Must use higher die | 2 on 22; 2 on 4; 2 on 5; 9 on 19 | Both `bar → 24` and `bar → 23` | Only `bar → 23`: neither entry allows a second move, so use 2 |

Reproduce with `createPositionState({ placements, bar: { white: 1 }, dice: [1, 2], mode: 'vs-human' })`, then inspect `getLegalMoves(state)` and `applyMove` for each returned move.

Fix at the shared turn-generation layer: enumerate usable continuations, retain first moves achieving maximum dice usage, and apply the higher-die rule when only one die can be used. Cover doubles, bar entry, bearing off, both colors, and compound paths. Keep raw single-step generation separate from turn legality to avoid recursive `applyMove`/`getLegalMoves` calls. Benchmark the search and compare against an independent rules oracle before merging.

Rule source: [U.S. Backgammon Federation](https://usbgf.org/backgammon-basics-how-to-play/). **Treat this as a release blocker. It is not fixed by this startup branch.**

### P1 — Games and review history can disappear

- `use-persist-active-game.ts` calls `clearActiveGame()` at game-over; that function also deletes the move log and replay baseline. Review survives only in memory, and is lost on relaunch. Archive the completed game first; show a result screen with review and rematch.
- Learn hub “Skip to play” and graduation “Play your first game” call `startGame` directly. That clears the existing save and turns on beginner aids. Home has a confirmation, but these paths bypass it. Route all new-game entry points through one confirmation/session policy. Keep practice separate from the active game.
- State, log, and baseline are separate storage writes. Add a versioned session record with validation and migration, plus recovery from an interrupted write. Archive by session ID. Existing [#73](https://github.com/softwarebyze/Backgammon-Mastermind/issues/73) covers multiple active games; [#97](https://github.com/softwarebyze/Backgammon-Mastermind/issues/97) covers bookmarked positions.

### P1 — Valid JSON can still crash restoration

`src/lib/storage.tsx:getItem<T>` only validates JSON syntax. `loadActiveGame` accepts any truthy object and only backfills `openingRolls`; `loadMoveLog` accepts any JSON value as an array. For example `{}` can become a “resumable” state despite missing `points`, and a non-array move log will fail when traversed. Validate shape, phases, dice ranges, point counts, and invariants at the persistence boundary. Quarantine an invalid save and explain recovery without blocking home.

### P1 — Resume reports success from inside a state updater

`use-game-lifecycle.ts:resumeGame` mutates `canResume` inside `setState(current => ...)` and immediately returns that boolean. React does not guarantee that updater runs before the return. The updater also calls other state setters/storage loaders. Read/validate the candidate synchronously outside the updater, then commit a single transition and return its result. Add a resume test with queued/batched state updates. This is a code-contract finding; the normal already-hydrated home path often avoids it.

### P1 — Replay is not analysis; the computer is not an expert coach

`src/lib/game/ai.ts` uses hand-tuned heuristics and searches the remaining checker moves in the current roll. It does not evaluate future opposing rolls or produce calibrated equity, win probabilities, or error rates. There is no selectable difficulty or match/cube state in `GameState`.

Keep the casual opponent, label its level honestly, and build stronger analysis behind an engine interface. Validate a reference position set before showing “best move,” equity, or blunder grades. Add match scores, gammon/backgammon scoring, doubling/cube ownership, Crawford handling, and resignation as deliberate game-model features. Do not present heuristic score differences as equity.

### P2 — The default experience underserves both beginners and regulars

- Fresh defaults turn off hints, point numbers, and direction guidance. A direct “vs Computer” start bypasses Learn. Offer “New to backgammon” / “I know the rules” once, with an obvious way to change it. Make legal destinations clear even without completing a curriculum.
- Four of five Learn topics are locked initially. Let a returning player jump directly to “How do I enter from the bar?”; keep an optional guided path. The previous Learn-removal PR [#139](https://github.com/softwarebyze/Backgammon-Mastermind/pull/139) was closed unmerged; this audit covers the Learn implementation still present on main.
- Normal computer pacing adds 600 ms thinking + 1,100 ms move delay + 720 ms animation per later checker. Most of this is presentation, not computation. Offer clear Relaxed/Quick pace at game setup; retain a readable settle animation and a skip affordance. Test the opening ceremony separately from app startup.
- On desktop, the home screen has substantial empty space while landscape hides descriptive text. Use that space for a useful saved-game card, recent results, or a compact next-practice action once those features exist. On phones, prioritize Resume and Play above secondary actions.
- A game should end with a result, a useful review entry point, and one next action. The current primary game-over action is Play Again.

### P2 — Accessibility and localization need behavioral QA

Board-point labels are a good start. However, the source has no reduced-motion handling, and several labels/captions remain English. Tiny checker geometry also needs testing with large text and motor accessibility. Verify VoiceOver/TalkBack move selection, die values and remaining dice, bar entry, bear-off, disabled actions, and review navigation on devices. Preserve board orientation semantics when switching RTL languages.

Continue existing [#77](https://github.com/softwarebyze/Backgammon-Mastermind/issues/77), [#86](https://github.com/softwarebyze/Backgammon-Mastermind/issues/86), and [#140](https://github.com/softwarebyze/Backgammon-Mastermind/issues/140). A count of translated files is not evidence that each language works.

### P2 — Finish the startup architecture and set a performance budget

Home still mounts the complete game provider and parses persisted state, move history, and baseline. The initial JS graph also includes bottom-sheet/keyboard infrastructure and route UI. Next, split a tiny session summary/actions store from board-only orchestration and lazy-load review/lessons/settings at real boundaries. Scope keyboard/sheet providers to their consumers. Measure before adopting global `inlineRequires`, since this app has theme/i18n/analytics import side effects.

The heuristic AI executes synchronously on the JS thread; a timeout only delays it. Initial-board probes here were roughly 0.2–1.5 ms median depending on the roll, so they do **not** establish a current AI bottleneck. Benchmark complex positions on phones before adding workers or deeper search.

Suggested acceptance targets, not achieved claims: native cold-launch p95 ≤1 second on a declared device set; warm resume p95 ≤200 ms; touch feedback within 100 ms; no gameplay action blocked by analytics or font network requests. Record OS launch → first visible frame → usable home → usable board separately, with 20+ runs on release builds, first install and long saved game, online and airplane mode. Include an older Android device, not only a high-end iPhone.

## What would make it fantastic

1. **Trustworthy play:** correct full-turn legality; no lost games; predictable undo/resume; complete scoring and cube rules.
2. **Fast, comfortable play:** instant home, immediate touch feedback, explicit pace, readable board, accessible inputs, polished offline behavior.
3. **A reason to return:** after a game, surface three meaningful mistakes with explanations; let the player retry each position; revisit weak concepts in short practice sessions. This requires validated analysis, not just the current heuristic.
4. **Useful personal history:** recent games, bookmarks, `.mat` import/export, and shareable positions. Build on the existing replay work and [#98](https://github.com/softwarebyze/Backgammon-Mastermind/issues/98).
5. **Evidence of quality:** integrate rule regressions, release-device startup measurements, and phone/tablet/web visual baselines into CI ([#87](https://github.com/softwarebyze/Backgammon-Mastermind/issues/87)). Track real successful starts after confirmation, first completed game, resume success, review-to-practice conversion, and crashes. `game_started` currently fires before the new-game confirmation, so canceled starts inflate it.

Recommended order: correctness and save safety → device performance gate → game results/history → validated analysis/practice → social/visual extras. Keep the offline, account-free advantage.
